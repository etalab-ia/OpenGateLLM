<Aside type="note" title="Optional dependency">
Langfuse is an **optional dependency** for OpenGateLLM. The application works without it.
</Aside>

OpenGateLLM supports [Langfuse](https://langfuse.com/) for LLM observability. It doubles as an alternative usage backend: as soon as this dependency is configured, inference usage is recorded in **and read from** Langfuse as generation observations, instead of the PostgreSQL `usage` table.

When this dependency is not configured, usage stays on the PostgreSQL `usage` table.

PostgreSQL remains required for application data (users, keys, routers, providers) and for budget deduction, which always stays on PostgreSQL. Only the usage backend changes.

## What is recorded

Each model-forward request (chat completions, embeddings, OCR, rerank, audio transcriptions) becomes a Langfuse **generation** observation:

| Field | Content |
| --- | --- |
| Name | Endpoint slug, for example `chat-completions` or `embeddings` |
| Model | Router name |
| User | Authenticated numeric user ID |
| Metadata | Full endpoint path, router ID and name, user email, key ID and name, provider ID and model name, HTTP status |
| Usage | Prompt tokens, completion tokens, cached prompt tokens |
| Cost | Request cost |
| Scores | `kWh` and `kgCO2eq` environmental impacts |
| Time to first token | Set on streaming chat as `completion_start_time` |
| Errors | Failed inferences are marked `ERROR` with the domain error name |

Prompts and completions are not sent to Langfuse.

## Langfuse as the usage source

Once this dependency is configured, Langfuse becomes the usage backend automatically. OpenGateLLM then records usage as generation observations and serves `GET /v1/usage` (and the Playground *Usage* page) by querying Langfuse — successful requests only, aggregated into daily buckets, with the same filters as PostgreSQL (user, time range, endpoint, models, key).

Requests are never dual-written: only the selected backend receives usage. When the Langfuse dependency is not configured, nothing is written to Langfuse and usage stays on PostgreSQL.

Environmental impacts (`kWh`, `kgCO2eq`) are stored as numeric scores and aggregated into the daily buckets through a second query against Langfuse's numeric-scores metrics, so usage reports keep the same shape as with PostgreSQL.

At startup, OpenGateLLM authenticates against the Langfuse server. If authentication fails, a warning is logged; usage reads and writes still target Langfuse when the dependency is configured.

## Configuration

Add Langfuse to the `dependencies` section of your `config.yml` file.
Check the [Langfuse section](/configuration/configuration_file/#langfusedependency) in the configuration file documentation for more details.

Example:

```yaml
dependencies:
    [...]
    langfuse:
        public_key: ${LANGFUSE_PUBLIC_KEY}
        secret_key: ${LANGFUSE_SECRET_KEY}
        base_url: http://localhost:3000
```

Create the API keys in your Langfuse project settings. `base_url` should point at your self-hosted Langfuse instance or at [Langfuse Cloud](https://cloud.langfuse.com).

Extra attributes are forwarded to the [Langfuse Python SDK](https://python.reference.langfuse.com/langfuse).
