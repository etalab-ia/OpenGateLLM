<Aside type="note" title="Optional dependency">
Langfuse is an **optional dependency** for OpenGateLLM. The application works without it.
</Aside>

OpenGateLLM supports [Langfuse](https://langfuse.com/) for LLM observability. It can be used as an alternative usage backend: with `settings.usage_source: langfuse`, inference usage is recorded in **and read from** Langfuse as generation observations, instead of the PostgreSQL `usage` table.

Selecting Langfuse as the usage source requires this dependency to be configured; otherwise OpenGateLLM fails to start. Configuring this dependency while keeping `usage_source: postgres` (the default) leaves usage on PostgreSQL and does not write usage observations to Langfuse.

PostgreSQL remains required for application data (users, keys, routers, providers) and for budget deduction, which always stays on PostgreSQL. Only the usage backend changes.

## What is recorded

Each model-forward request (chat completions, embeddings, OCR, rerank, audio transcriptions) becomes a Langfuse **generation** observation:

| Field | Content |
| --- | --- |
| Name | Endpoint slug, for example `chat-completions` or `embeddings` |
| Model | Router name |
| User | Authenticated numeric user ID |
| Metadata | Full endpoint path, router ID and name, user email, key ID and name, provider ID and model name, HTTP status |
| Usage | Prompt tokens, completion tokens, cached prompt tokens |
| Cost | Request cost |
| Scores | `kWh` and `kgCO2eq` environmental impacts |
| Time to first token | Set on streaming chat as `completion_start_time` |
| Errors | Failed inferences are marked `ERROR` with the domain error name |

Prompts and completions are not sent to Langfuse.

## Langfuse as the usage source

Set `settings.usage_source: langfuse` to make Langfuse the usage backend. OpenGateLLM then records usage as generation observations and serves `GET /v1/usage` (and the Playground *Usage* page) by querying Langfuse — successful requests only, aggregated into daily buckets, with the same filters as PostgreSQL (user, time range, endpoint, models, key).

Requests are never dual-written: only the selected backend receives usage. With `usage_source: postgres` (the default), nothing is written to Langfuse.

<Aside type="caution" title="Environmental impacts">
`kWh` and `kgCO2eq` are stored as Langfuse scores, which the usage query API cannot aggregate, so they are reported as `0` in the daily usage buckets. Keep `usage_source: postgres` if you need environmental impacts in usage reports.
</Aside>

At startup, OpenGateLLM authenticates against the Langfuse server. If authentication fails, a warning is logged; usage reads and writes still target Langfuse when it is the selected source.

## Configuration

Add Langfuse to the `dependencies` section of your `config.yml` file.
Check the [Langfuse section](/configuration/configuration_file/#langfusedependency) in the configuration file documentation for more details.

Example:

```yaml
dependencies:
    [...]
    langfuse:
        public_key: ${LANGFUSE_PUBLIC_KEY}
        secret_key: ${LANGFUSE_SECRET_KEY}
        base_url: http://localhost:3000
```

Create the API keys in your Langfuse project settings. `base_url` should point at your self-hosted Langfuse instance or at [Langfuse Cloud](https://cloud.langfuse.com).

Extra attributes are forwarded to the [Langfuse Python SDK](https://python.reference.langfuse.com/langfuse).
